A project's weak points are not always in its own code. They can come from a dependency, a file written by a tool, or a provider nobody has heard of. Several recent announcements make this clear: a new safeguard in Cargo, secrets exposed by a coding agent, and a data breach that reached Notion.

## Rust 1.100: Cargo learns to wait

Rust 1.100.0 shipped yesterday, November 12. It stabilizes the never type, written `!`. According to the [official announcement](https://blog.rust-lang.org/2026/11/12/Rust-1.100.0/), this took ten years and five abandoned attempts. Developers can now write `Result<T, !>` for an operation that cannot fail, and `Infallible` becomes a plain alias of `!`. In the 2015 to 2021 editions, a default behavior changes and can occasionally break code. Updating the affected dependency is often enough. An [LWN article](https://lwn.net/Articles/1091015/) from September had expected this change in 1.99.

The core of the `Allocator` API is also stable. Custom allocators can now be used with `Vec` and `Box`, which is useful for embedded work and games. `DropGuard` runs an action when a value is dropped, and Cargo now reports unused dependencies (test dependencies are not covered).

The most important change for security is the `global-min-publish-age` option. Setting it to a value such as `"3 days"` in `.cargo/config.toml` tells Cargo to ignore versions published less than three days ago. Malicious releases of popular packages are often caught within hours or days, so waiting lowers the risk. The announcement notes that this is not complete protection.

## Claude Code: passwords copied into a settings file

Research by Apiiro, reported by [The Hacker News](https://thehackernews.com/2026/11/claude-codes-dont-ask-again-file.html) and [RuntimeWire](https://runtimewire.com/article/claude-code-dont-ask-again-secrets-public-github-settings-files), looks at Claude Code's "Yes, and don't ask again" option. When a user picks it, the tool copies the exact command into `.claude/settings.local.json`. If the command included a password, the password is stored in plain text. The file is added to the machine's global Git exclusion list, but never to the project's `.gitignore`, so it can still end up on GitHub.

Apiiro found 104,185 copies of the file in public repositories. Of these, 1,122 held at least one secret, for a total of 1,379 distinct secrets: 379 database passwords, 43 SSH credentials, 42 GitHub, GitLab or npm tokens, and 23 AWS keys. Standard scanners miss some of them: gitleaks flagged 564 of the 1,122 affected copies and TruffleHog flagged 643. An issue reporting the problem was opened in August 2025 and later closed automatically for inactivity. The reports do not include a response from Anthropic.

## Fireworks AI: a breach three steps removed

According to [The Register](https://www.theregister.com/cyber-crime/2026/11/10/fireworks-ai-gets-burned-twice-as-customer-data-exposure-widens/5308722), the inference provider Fireworks AI was breached twice in October. In the first incident, attackers read environment variables that held customer API keys. In the second, they got in through a cloud provider that hosted Fireworks research machines, then moved into its development systems. [TechCrunch](https://techcrunch.com/2026/11/12/cyberattack-on-fireworks-ai-allowed-hackers-to-access-notion-customers-chat-transcripts/) reports that Notion has confirmed the theft of conversations with its AI assistant, affecting about 1% of its customers. Notion cut ties with Fireworks on November 3. The total number of affected customers is unknown.

## AI-found vulnerabilities: triage is still human work

[VulnCheck](https://www.vulncheck.com/blog/anthropic-glasswing-november-update) has published a review of Project Glasswing, Anthropic's effort to find vulnerabilities in open source software. As of November 2, the project's registry listed 37,966 findings: 7,349 made public and only 217 fixed. In September, the AI rated 91.5% of its findings as critical or high, while maintainers rated 51.3% that way. curl, for example, received 45 reports. Of the 34 made public, 19 were not vulnerabilities. These findings are disputed, since VulnCheck has a commercial interest. In June, the [Cloud Security Alliance](https://labs.cloudsecurityalliance.org/research/csa-research-note-glasswing-ai-vuln-patching-deficit-2026060/) reported that independent experts had judged 90.6% of 1,752 reviewed findings to be valid.

## Red Hat Quay: one unescaped SQL character

Red Hat has fixed two flaws rated 9.8 and 9.9 out of 10 in Quay, its container registry, [The Hacker News](https://thehackernews.com/2026/11/critical-red-hat-quay-flaw-lets.html) reports. The first lets an attacker, often without an account, add their own trusted key and then read and replace private images. The second comes from an unescaped underscore in a SQL query. In SQL, that character matches any single character, which exposed other customers' tokens.

## Analysis

These stories share one point: more and more of the risk sits around the code rather than in it. For a TypeScript and Node.js stack, Cargo's publish delay is worth watching, because npm faces the same kind of attack, and this safeguard costs nothing. The Claude Code case leads to two simple rules. Never type secrets into commands; use environment variables instead. Add files generated by agents to `.gitignore` explicitly. If a secret leaks, replace it first, then clean the Git history.

The Fireworks breach raises a separate question: what data is sent to an AI provider, and who hosts that provider? This applies directly to apps that call external models, such as [NEXUS](/nexus), Melchior JORDA's self-hosted assistant, which relies on Gemini and Claude. Finally, the Glasswing review shows that finding vulnerabilities keeps getting cheaper, while checking and fixing them is still human work. The value of these reports will depend on their quality more than their number.
