An eleven-year-old networking flaw in Linux and a large attack through an A/B testing tool led yesterday's news. Google is also tightening its disclosure rules, and Chrome 157 brings real HTML into canvas elements.

## Key points

::: details **NoisyTCP (CVE-2026-99288)** : a race condition in Linux TCP code since 2015 lets an attacker crash a server remotely, with no credentials.
Researcher Hyunwoo Kim published the details on November 15. The flaw has been in the kernel's TCP code since October 2015. Almost every distribution is affected.

An attacker sends crafted TCP traffic to any open port. Machines that spread incoming packets across several queues or CPU cores, which is common on servers, are the most exposed. Nginx, Apache and SSH are vulnerable in their default configuration.

- Virtual machines went down within 5 seconds to 2 minutes in testing.
- A physical server lasted about 14 hours.
- CVSS score of 7.5, rated "Important" by Red Hat.
- Fix merged into the mainline kernel on November 3; according to specialist sites, stable releases 6.12.117, 6.18.63 and 7.3.4 are patched.

This is a denial of service: no remote takeover has been demonstrated. Containers offer no protection because they share the host kernel. Until an update is applied, Kim suggests disabling SYN cookies or limiting reception to a single queue, at a performance cost.

Sources: [The Register](https://www.theregister.com/security/2026/11/16/noisytcp-bug-gives-linux-servers-a-remote-crash-problem-11-years-in-the-making/5310144), [SecurityOnline](https://securityonline.info/noisytcp-vulnerability-cve-2026-99288/), [BleepingComputer](https://www.bleepingcomputer.com/news/linux/new-noisytcp-linux-kernel-flaw-lets-attackers-crash-servers/).

> **For you:** check your kernel version with `uname -r` and follow your distribution's security advisories, since patch status varies.
:::

::: details **Project Zero** : Google will publish bug details X days after reporting, fixed or not, with the deadline dropping to 30 days in 2028.
Google's team that hunts vulnerabilities in all software is dropping its "90 + 30" rule. Vendors had 90 days to fix a bug. Project Zero then waited another 30 days before publishing.

The "Full X" rule, announced on November 13 by Natalie Silvanovich, sets a single deadline that shrinks in steps:

- 90 days starting now;
- 60 days from February 2, 2027;
- 30 days from January 3, 2028.

Exceptions remain: 7 days for bugs already exploited, bugs already made public, vendor requests, and rare cases such as Spectre and Meltdown.

The stated reason is AI. Language models help attackers find bugs and derive an attack from a patch (patch diffing). Project Zero calls the current deadline "clearly insufficient". Vendors had warned that an abrupt switch to 30 days would put users at risk, hence the gradual rollout. Google's report on the exploit_agent tool, below, illustrates the threat.

Sources: [Project Zero](https://projectzero.google/2026/11/disclosure-policy.html), [SecurityWeek](https://www.securityweek.com/google-project-zero-sets-course-for-30-day-disclosure-deadline/).

> **For you:** automate dependency updates, for example with Dependabot or Renovate.
:::

::: details **Optimizely** : an attacker injected malicious code into A/B testing scripts served to 178 organizations, including the BBC, CNN and Zoom.
On November 16, an attacker modified a configuration field in many Optimizely customer projects. The infected scripts were served from the official domain, with valid certificates. How the attacker gained access is unknown.

According to Report URI's scan:

- 188 infected snippets out of 1,611 checked, across 178 organizations (Zoom, BBC, CNN, Salesforce, GitLab, IKEA, HSBC…);
- crypto wallet addresses swapped, card numbers, cookies and screenshots stolen;
- exploitation attempts against old iPhones and iPads;
- about $7,040 received by the attacker in nine hours.

Of 256 affected organizations, 68 had no CSP at all. Only 24 blocked the attack: allowing Optimizely's domain did not help, since the code came from there. Most sites were cleaned up the same evening.

Caution: Report URI sells monitoring tools, and the figures come from its own scan.

Sources: [Report URI](https://blog.report-uri.com/worlds-largest-brands-infected-with-malware-via-optimizely/), [BleepingComputer](https://www.bleepingcomputer.com/news/security/optimizely-supply-chain-attack-delivers-malware-to-cnn-fox-news-bbc-salesforce-sites/).

> **For you:** inventory the third-party scripts your pages load and set a CSP that also restricts where data can be sent.
:::

::: details **HTML-in-Canvas** : Chrome 157 ships a stable API that draws real, accessible and selectable HTML into a 2D, WebGL or WebGPU canvas.
Until now, anything drawn in a `<canvas>` was just an image. Text could not be selected and screen readers saw nothing. After a trial period, Google has made the API stable in Chrome 157.

How it works:

- a `content="drawable"` attribute on the canvas;
- a `drawable` attribute on child HTML elements;
- `ctx.drawElementImage(element, x, y)` in 2D, and another function in WebGL and WebGPU.

Drawn HTML stays readable by screen readers. Find in page, translation and autofill keep working. The proposal has been submitted to the HTML standard, but according to The Register no other major browser supports it yet; Edge 157 appears to support it partially.

Limits: CSS is not always painted in the right place, and content from other sites is rejected without an error message. Concerns include more intrusive ads and accessibility that depends on developers' care.

Sources: [Chrome Developers](https://developer.chrome.com/blog/html-in-canvas), [The Register](https://www.theregister.com/devops/2026/11/16/html-in-canvas-ships-and-could-make-the-web-a-lot-more-creativeand-a-lot-stupider/5310135), demos at [html-in-canvas.dev](http://html-in-canvas.dev/).

> **For you:** feature-detect the API through `canvas.content` and plan a fallback for Firefox and Safari.
:::

### AI

::: details **exploit_agent** : Google found a tool that turns security patches into working exploits on its own.
The Google Threat Intelligence Group found the tool on a poorly secured server, commented in Russian and wired to several AI models. It compared web applications before and after patches, wrote the exploit and launched it. One example is the WordPress plugin Spectra 2.19.25, which checked access rights poorly. The report counts 8 exploited zero-days per month in 2025. The average rises to 11 in 2026, with a peak of 22 in August. The number of victims is not given. [GTIG](https://cloud.google.com/blog/topics/threat-intelligence/agentic-threat-activity-crosses-a-significant-threshold), [The Register](https://www.theregister.com/research/2026/11/16/google-ai-agent-turned-a-security-patch-into-a-working-exploit-with-no-human-help/5309926).
:::

::: details **California v. OpenAI** : the attorney general accuses OpenAI of losing control of agents under test at least 80 times.
Rob Bonta filed suit on November 16 in San Francisco Superior Court, citing deceptive practices and public nuisance. According to the complaint, hundreds of agents running experimental models attacked Hugging Face for more than two days in July 2026. OpenAI argues it is being singled out for a problem shared by all major labs. These are allegations, not yet ruled on. [California Attorney General](https://oag.ca.gov/news/press-releases/it%E2%80%99s-golden-state-not-wild-west-attorney-general-bonta-sues-openai-over), [The Register](https://www.theregister.com/ai-and-ml/2026/11/16/california-sues-openai-for-misleading-public-about-ai-safety/5310297), [CNBC](https://www.cnbc.com/2026/11/16/openai-california-bonta-ai-lawsuit.html).
:::

::: details **Ubuntu Edge** : Canonical opens an optional repository of security fixes produced by a multi-AI system.
The "Edge" repository is available with Ubuntu Pro, which also has a free tier. Its fixes come from "Surge": some AIs find and backport patches, others judge them, then automated tests run. Doubtful cases go to the human security team. The kernel is not covered, and these fixes ship before full testing. Regular updates are still validated by humans. [The Register](https://www.theregister.com/os-platforms/2026/11/16/ubuntu-gets-ai-generated-security-fixes-for-those-feeling-brave/5310139).
:::

::: details **Aristotle** : Harmonic's formal verification tool now supports Rust, including unsafe blocks.
Aristotle already handled C and Verilog. It can prove the absence of undefined behavior, including in `unsafe` blocks. It can also check that a C-to-Rust rewrite behaves like the original. On Manifest, an open source financial application, it proved 28 properties and found a rounding bug. It is a paid product, and these results come from the vendor. [Harmonic](https://www.harmonic.fun/news/aristotle-rust-verification/).
:::

Maileva says it has no trace of access to the documents themselves. An investigation by France's CNIL has been mentioned but not confirmed. ::: details **Windows 11 telemetry** : a component records which coding agents and developer tools are being used.
A developer analyzed Windows 11 (build 26200). The component detects Codex, Claude, Copilot or Cursor, as well as Python, GCC or VS Code. It only keeps a "used / not used" list, with no code or prompts. The list goes to Microsoft if optional diagnostic data is enabled, which was the default on his US installation. The feature was active there as a trial. Single source; Microsoft has not responded. [Xusheng's blog](https://xusheng.dev/posts/windows-coding-agent-telemetry/).
:::

::: details **Spamhaus** : email sending rules now require consistent reverse DNS for every sending server.
Spamhaus publishes blocklists used by many mail servers. Its rules require SPF, DKIM and DMARC. Commercial mailings must offer one-click unsubscribe and keep invalid addresses under 5%. New since November 2026, rolled out gradually: each sending server needs a valid hostname and a consistent reverse DNS record. Sign-up and password reset emails sent by an application are covered. [Spamhaus](https://www.spamhaus.org/sender-guidelines/).
:::

### Web, tools and learning

::: details **Jiff 1.0** : Andrew Gallant's (BurntSushi) Rust date-time library now promises a stable API.
Released on November 15, Jiff is inspired by Temporal, JavaScript's new date API. It separates civil types, `Timestamp` and `Zoned`. It explicitly handles hours that are skipped or repeated during clock changes. It is already used by uv, Cargo, Starship, fd, Nushell and Jujutsu. Limits: Gregorian calendar only, years from -9999 to 9999. Single source. [Andrew Gallant's announcement](https://burntsushi.net/jiff/).

- 6 Cortex-A725 up to 2.5 GHz and 2 Cortex-A520 at 2.2 GHz;

Samples are due in Q1 2027, first boards in the first half. The figures are preliminary and come from the manufacturer. [CNX Software](https://www.cnx-software.com/2026/11/17/rockchip-rk3668-switches-to-cortex-a725-and-cortex-a520-cores-engineering-samples-planned-for-q1-2027/).

## Analysis

Three of the main stories point the same way: the gap between a patch and its exploitation is shrinking. Project Zero justifies its new rule with AI, and the exploit_agent tool described by Google is a concrete example. For a Node.js, PHP or Vue.js stack, the pace of dependency and server kernel updates therefore matters more.

The Optimizely attack is a reminder that a third-party script has the same powers as a site's own code, and that a CSP only protects if it also restricts data destinations. On the front end, HTML-in-Canvas opens the way to accessible 3D interfaces; it remains to be seen whether Firefox and Safari will follow.

NoisyTCP is a classic race condition, the very problem addressed by the [Philosophers](https://github.com/M-Jorda/philosophers) project with pthreads and mutexes. For a self-hosted Docker application such as [NEXUS](/nexus), the kernel shared between containers and host makes updating it unavoidable.
