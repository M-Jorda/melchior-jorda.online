Two out-of-bounds memory write bugs lead this edition: one is in the JVM, the other in industrial refrigeration controllers. On the tooling side, Rust speeds up compilation and a study measures how quickly keys published on Docker Hub get stolen.

## Key points

::: details **Java4Shell**: a critical flaw in OpenJDK's Base64 decoding enables remote takeover of Jenkins, Jira or Keycloak.
On 17 November, security firm Calif disclosed CVE-2026-114938, nicknamed Java4Shell. The bug sits in the JIT intrinsic that decodes Base64. Only x86-64 processors with AVX-512 VBMI are affected (Intel Xeon since Ice Lake, AMD since Zen 4). ARM servers are not affected.

With a short input ending in "=", a length calculation becomes negative. The write mask then switches to "write everything". Memory is corrupted before the input is even rejected.

- Affected versions: OpenJDK 17.0.6 onwards, the base of most distributions (Oracle, Corretto, Temurin…).
- Severity: 9.2 according to Calif, 8.1 according to Oracle.
- Unauthenticated takeover in default configuration: Keycloak, Jira, Confluence, Jenkins, Artifactory, PingFederate.
- Found with OpenAI's Codex: about 1 hour for the bug, 2 more hours for a working exploit.
- Compute cost: under 200 dollars.

Oracle shipped the fix the same day in its quarterly update. There is no universal exploit, because each application must be made to decode the crafted input. Calif only released a demonstration of the bug, so the number of actually exploitable applications is unknown. Until you can update, the -XX:-UseBASE64Intrinsics or -XX:UseAVX=2 options disable the faulty code.

Sources: [Calif](https://calif.io/java4shell/) and [BleepingComputer](https://www.bleepingcomputer.com/news/security/critical-java4shell-flaw-allows-rce-attacks-on-major-java-applications/).

> **For you:** check your JDKs with java -version and apply your distribution's update.
:::

::: details **Danfoss controllers**: six remote code execution flaws were found in under an hour in a refrigeration controller firmware.
Carlo Meijer of Midnight Blue reviewed firmware 5.3.2, the latest version, of the Danfoss AK-SM800A. This Linux box running on an NXP i.MX6 drives cold rooms and refrigerated displays. He says he did not use AI.

- All six flaws allow unauthenticated remote code execution.
- Five come from strcpy() calls in the web application.
- The sixth affects the session control filter.
- The process runs as root, without stack canaries or PIE, and without secure boot.

An attacker could therefore stay on the device across reboots, or brick it.

In France, attackers have been triggering defrost cycles on refrigeration controllers since 11 October (CERT-FR alert). A second wave followed on 2 November. Supermarkets and blood banks were hit. Censys lists hundreds of exposed Danfoss systems, plus over a thousand from Copeland and Dixell, some of them researcher honeypots. Patches are "pending". The researcher and the authorities advise taking these devices off the Internet and using a VPN.

Sources: [Midnight Blue](https://www.midnightblue.nl/blog/multiple-rce-danfoss-aksm800a) and [The Register](https://theregister.com/security/2026/11/17/not-rocket-surgery-claims-researcher-who-found-six-danfoss-fridge-controller-zero-days-in-under-an-hour/5310197).

> **For you:** in C, replace strcpy() with bounded copies such as snprintf(), build with -fstack-protector-strong -fPIE -pie and check your binaries with checksec.
:::

::: details **Rust**: rustc's parallel frontend is now enabled by default on nightly, making cargo check up to 44% faster.
The compiler team announced on 16 November that the parallel frontend has been on by default since the 14 November nightly, with 2 threads. The frontend parses code, checks types and runs the borrow checker. It used to run on a single core, while the LLVM backend was already parallel. The option has existed [since 2023](https://blog.rust-lang.org/2023/11/09/parallel-rustc/), but had to be enabled by hand.

Reported gains for a crate built from scratch with cargo check:

- 2 threads: 22% faster;
- 4 threads: 38%;
- 8 threads: 44%;
- optimized build with 8 threads: 28%.

Incremental rebuilds, the everyday case, only gain 3 to 5%. On the whole cargo project, checking drops from 36.7 s to 30.8 s, because cores are already busy with other crates.

The setting is -Zunstable-options --jobs-frontend=8. Beyond 8 threads, gains plateau and memory use climbs. Two issues are known: error message order can vary, and some binaries are no longer reproducible, which the team treats as a bug. Stabilization is planned within a few months, with no set date.

Source: [Rust blog](https://blog.rust-lang.org/2026/11/16/enabling-parallel-frontend-on-nightly/).

> **For you:** compare cargo +nightly check with cargo check on your projects and report any crash on GitHub issue #113349.
:::

::: details **Docker Hub**: cloud keys left in public images were first abused less than 8 seconds after publication.
Billy Tsouvalas and Nick Nikiforakis of Stony Brook University presented the study "Gone in 8 Seconds" at ACM CCS. Over four months, they published 300 bait images on eight public registries. The images held fake AWS, OpenAI and Anthropic keys, plus SSH and database credentials.

- Over 75,000 downloads.
- Over 140,000 calls on the AWS keys, from about 5,000 IP addresses.
- First use: 7.86 seconds after publication.
- Half of the keys used within 51 seconds.
- All 100 AWS keys abused within 15 minutes.

The OpenAI and Anthropic keys were used to drain account credits. Bots almost never run the containers. They read the layers directly, where a file deleted later remains readable. Docker Hub accounts for nearly all the activity.

Docker was notified in May and only sent an acknowledgement. A new test in August showed no change. The report comes from a single outlet, but the study data is public.

Sources: [BleepingComputer](https://www.bleepingcomputer.com/news/security/cloud-keys-leaked-in-docker-hub-images-are-stolen-within-seconds/) and [data on Zenodo](https://zenodo.org/records/24052862).

> **For you:** never write secrets into a Dockerfile, use .dockerignore and RUN --mount=type=secret, and revoke any published key immediately, even if it was exposed only briefly.
:::

## Other news

Most of the remaining news is about AI: infrastructure, model security and a retreat from open weights. Hugging Face now routes its language model traffic through OpenRouter, while Alibaba keeps its most powerful model closed. The Kokoro account hijack shows that model weights are a dependency like any other. On hardware and regulation, double precision is back at the center of HPC, Waymo loses California freeways and France passes its NIS2 law.

### AI

::: details **Hugging Face and OpenRouter**: language model requests now go through OpenRouter.
Since 16 November, Inference Providers has routed language model requests through OpenRouter. OpenRouter picks among more than 80 providers based on price, speed and reliability. Billing stays with Hugging Face, at provider price with no markup. OpenAI and Anthropic API formats are supported, with :fastest and :cheapest suffixes. Breaking change: personal provider keys can no longer be used for these models. Single source: [Hugging Face blog](https://huggingface.co/blog/openrouter).
:::

::: details **Kokoro**: a popular Hugging Face account was hijacked through an expired domain name.
Kokoro, a text-to-speech model, is downloaded nearly 13 million times a month. Researcher Alon Hertz and his team bought the domain listed in a project file. They then reset the password of the account, inactive since April 2025. They altered the weights in 87 seconds and tested them only locally. No antivirus would flag this trap, as it contains no code. Single source: [BleepingComputer](https://www.bleepingcomputer.com/news/security/researchers-hijack-hugging-face-account-for-popular-kokoro-ai-model/).
:::

::: details **Qwen4-Max**: Alibaba launches a 2.4-trillion-parameter model without open weights.
Released on 16 November, Qwen4-Max is a mixture-of-experts model with 71 billion active parameters per token. Its context window reaches one million tokens, and it accepts images and video.

- Price: $1.5 input and $4.5 output per million tokens.
- Artificial Analysis index: 43, versus 65 for Claude Fable 5.2.

Unlike Qwen3.8-Max, its weights are not released. The claimed efficiency gains come from Alibaba's own tests. Sources: [Next](https://next.ink/267802/alibaba-qwen4-max-2-400-milliards-de-parametres-et-une-table-n-gram-de-328-milliards/) and [Le Monde Informatique](https://www.lemondeinformatique.fr/actualites/lire-alibaba-lance-qwen4-max-son-nouveau-modele-d-ia-axe-sur-la-performance-et-la-securite.html).
:::

### Low level and hardware

::: details **Supercomputers and FP64**: NVIDIA bets on emulation, AMD on native double precision.
At SC26, NVIDIA unveiled Rubin HPC, due in 2028, with over 50,000 CUDA cores but no FP64 figure. The company is betting on emulation derived from the Ozaki method. It claims up to 200 TFLOPS of emulated FP64 for matrix multiplication. AMD claims 288 TFLOPS of native FP64 for the Instinct MI430X. NVIDIA also released Nemotron for Science, an open model. All figures come from the vendors. Sources: [SiliconANGLE](https://siliconangle.com/2026/11/16/nvidia-debuts-new-rubin-hpc-chip-scientific-research-libraries/) and [The Register](https://www.theregister.com/hpc/2026/11/17/gpu-giants-throw-hpc-users-some-tasty-crumbs/5310611).
:::

### Industry and regulation

::: details **Waymo**: California bans its robotaxis from freeways after repeated entries into work zones.
The California DMV issued the order on 11 November and made it public on the 17th. It cites an "imminent danger" after repeated entries into construction zones. A software fix had already followed a similar incident in May. Waymo is suspending freeway rides in all its cities, while city service continues. The ban stays until Waymo proves effective fixes. Sources: [TechCrunch](https://techcrunch.com/2026/11/17/waymo-suspends-freeway-rides-nationwide-after-california-dmv-order) and [The Robot Report](https://www.therobotreport.com/california-dmv-bars-waymo-avs-from-operating-on-the-states-freeways/).
:::

::: details **Resilience law (NIS2)**: the French National Assembly passes the transposition, without the encryption safeguard.
The bill transposes NIS2, DORA and CER.

- Sectors covered: from 7 to 18.
- Organizations covered: from about 600 to over 15,000.
- Serious incident: alert within 24 hours, report within 72 hours.

MPs removed article 16 bis, which banned imposing backdoors in encryption. The text still goes to a joint committee of both chambers. Sources: [Next](https://next.ink/268104/derniere-ligne-droite-pour-le-pjl-resilience-qui-passe-le-vote-solennel-a-lassemblee/) and [Journal du Net](https://www.journaldunet.com/cybersecurite/1557881-nis2-l-assemblee-adopte-enfin-la-transposition-et-la-reecrit-contre-l-avis-du-gouvernement/).
:::

## Analysis

Java4Shell and the Danfoss flaws share the same defect: a memory write past the intended buffer. The first hides in hand-optimized JIT code, the second in strcpy() calls on firmware without canaries or PIE. Both were cheap to find: under 200 dollars with AI, or under an hour without it.

Docker Hub and Kokoro show that published artifacts, whether image layers or model weights, are read and reused automatically. In a stack like [NEXUS](/nexus), which combines Docker with calls to Gemini or Claude, API keys and model versions are therefore sensitive points. It remains to be seen whether Docker Hub and Hugging Face will announce additional checks.

For Rust, the next steps to follow are the stabilization of the parallel frontend and the fix for non-reproducible builds.
