Ce digest est dominé par la sécurité : une clé publiée par un agent de code chez Together AI, puis deux failles d'exécution de code, dans Ghostscript et dans binary-parser. Côté langages, C++26 est de nouveau terminé après un vote international non unanime.

## L'essentiel

::: details **Together AI** : un agent de code a publié une clé secrète sur GitHub, et des échantillons de prompts de clients ont été volés.
Together AI, fournisseur d'inférence, a publié son [rapport d'incident](https://www.together.ai/blog/security-event-prompt-leakage-for-requests-in-june-and-july-of-2026). L'entreprise conservait des échantillons de prompts de clients pour ses tests, dans un dépôt privé sur Hugging Face. Pendant un développement, un agent de code a commité une clé d'accès à ce dépôt dans un dépôt public GitHub.

- Requêtes concernées : surtout celles des 24 juin, 4, 8 et 14 juillet 2026.
- Un scan automatique a repéré la clé et le commit a été annulé, mais elle avait déjà été récupérée.
- L'attaquant a cherché d'autres identifiants dans les échantillons, puis les a testés.
- Cinq d'entre eux étaient des canaris posés par Dragos : de faux secrets qui déclenchent une alerte.

Together ne précise ni le nombre de clients touchés ni la durée d'exposition. L'enquête continue avec la police et un cabinet extérieur. L'entreprise annonce des clés à durée courte, un scan de chaque modification et la non-conservation des données (ZDR) par défaut.

Le 22 novembre, [OpenRouter](https://openrouter.ai/blog/announcements/data-processing-incidents-on-inference-providers/) a écarté trois fournisseurs. Il a aussi retiré le label ZDR à 125 points d'accès.

> **Pour vous :** révoquez immédiatement toute clé commitée, même annulée, et soumettez les commits des agents de code aux mêmes contrôles de secrets (push protection de GitHub, gitleaks) que ceux des humains.
:::

::: details **Ghostscript** : la faille Upload2Shell permet de lancer des commandes sur un serveur à partir d'un simple fichier téléversé.
Le 21 novembre, les chercheurs de [pwn.ai](https://pwn.ai/upload2shell/research.html) ont détaillé la CVE-2026-125396, trouvée avec l'aide d'un modèle d'OpenAI. Une fonction de chargement des polices faisait une écriture privilégiée sans vérifier ses données. Une police piégée permet de contrôler la mémoire, de couper la vérification des fichiers et de lancer des commandes, alors que le bac à sable -dSAFER reste actif.

Le point d'entrée est un téléversement. ImageMagick ou Pillow peuvent confier à Ghostscript un fichier à extension « sûre » qui contient du PostScript. L'attaque a réussi sur dix produits, dont :

- l'impression réseau de Debian 13, avec un travail d'impression anonyme ;
- le webmail Roundcube, à la simple ouverture d'un e-mail ;
- WordPress avec certaines extensions, MediaWiki et DokuWiki.

Le correctif figure dans Ghostscript 10.08.0, sorti le 8 septembre. Selon [BleepingComputer](https://www.bleepingcomputer.com/news/security/ghostscript-flaw-lets-hackers-hijack-servers-via-pdf-uploads/), Debian 12, Amazon Linux et certaines versions de SUSE n'étaient pas corrigés au 12 novembre. La note est de 8,5 en CVSS 4.0, et de 7,8 dans d'autres bases, car la faille est classée « locale » alors qu'elle a été exploitée à distance (voir aussi la [fiche Red Hat](https://bugzilla.redhat.com/show_bug.cgi?id=2569593)).

> **Pour vous :** sur un serveur qui génère des miniatures de fichiers utilisateurs, vérifiez la version avec gs --version et interdisez les formats PS et PDF dans le policy.xml d'ImageMagick s'ils sont inutiles.
:::

::: details **binary-parser** : avant la version 2.3.1, cette bibliothèque npm insérait des options non contrôlées dans le code JavaScript qu'elle génère.
binary-parser décode des données binaires à partir d'une description. Pour aller vite, elle génère une seule fois du code JavaScript sur mesure, puis l'exécute. La CVE-2026-134814 vient de plusieurs options (longueur, clé, décalage, entre autres) collées telles quelles dans ce code.

Un attaquant qui contrôle la description peut donc exécuter son propre JavaScript sur le serveur. Selon le mainteneur, décoder des données hostiles avec une description écrite par le développeur reste sans danger. Sont concernées les applications où l'utilisateur décrit lui-même un format : analyse de protocoles, plateformes d'objets connectés.

- Le correctif n'accepte plus que des noms simples, comme foo ou $parent.len.
- Une expression comme len - 1 doit désormais passer par une fonction.
- La faille découle d'un correctif incomplet de la CVE-2026-1245, notée 6,5 et corrigée en janvier.
- La nouvelle reçoit deux notes selon la grille utilisée : 9,2 et 8,1.

Ces informations viennent d'une source unique, [The Hacker News](https://thehackernews.com/2026/11/critical-binary-parser-flaw-enables.html), qui s'appuie sur l'[avis du mainteneur](https://github.com/advisories/GHSA-xmxc-6c22-m377).

> **Pour vous :** lancez npm ls binary-parser puis npm audit dans vos projets Node.js, et traitez avec méfiance tout eval ou new Function alimenté par des données externes.
:::

::: details **C++26** : la norme est de nouveau terminée, après le premier vote des pays non unanime de l'histoire du C++.
Cinq pays ont voté contre le projet final (DIS), à cause des contrats. Ces contrats décrivent dans le code ce qu'une fonction exige et ce qu'elle garantit. Réuni à Búzios, au Brésil, avec environ 220 participants, le comité les a maintenus, selon le [compte rendu de Herb Sutter](https://herbsutter.com/2026/11/21/c26-is-done-again-trip-report-november-2026-iso-c-standards-meeting-buzios-brazil/), son président.

- Vote : 111 pour, 9 contre, 8 abstentions, soit 92,5 %.
- Soutien en février 2025 : 87,7 %.
- Soutien en mars 2026 : 90,5 %.

Une critique porte sur le fait qu'un contrat peut être vérifié ou ignoré selon la compilation. Le comité a ajouté une option pour marquer un contrat « toujours vérifié », ce qui y répond en partie. Un second vote des pays doit suivre, puis la publication, sans date précise ; les pays opposés et leurs objections ne sont pas connus.

C++26 apporte aussi la réflexion et std::execution ([Wikipédia](https://en.wikipedia.org/wiki/C%2B%2B26)). Déjà adoptés pour C++29 :

- le préfixe 0o pour l'octal (aujourd'hui, 010 vaut 8) ;
- des break et continue nommés ;
- std::ranges::any_view.

> **Pour vous :** compilez avec -std=c++26 et consultez [cppreference.com](http://cppreference.com/) pour savoir quelles nouveautés votre compilateur gère déjà.
:::

## Les autres sujets

La sécurité reste au premier plan, avec le rachat de Zscaler par CrowdStrike, une faille critique de ScreenConnect et un rançongiciel au CHU de Guadeloupe. En IA, plusieurs chiffres reposent sur une source unique ou une étude non relue : robots pilotés par des modèles généralistes, gros modèle sur carte grand public, effet des agents sur l'emploi junior. Microsoft réorganise ses outils, avec PowerShell 7 intégré à Windows et la fin de To Do. La régulation européenne et des principes pour l'IA à l'école complètent l'ensemble.

### Sécurité

::: details **CrowdStrike et Zscaler** : rachat annoncé pour environ 43,9 milliards de dollars, payé en actions.
Annoncé le 23 novembre ([dépôt SEC](https://www.sec.gov/Archives/edgar/data/0001535527/000153552726000035/crwd-20261123xex991.htm), [Next](https://next.ink/brief-article/crowdstrike-va-racheter-zscaler-pour-44-milliards-de-dollars/)). Chaque action Zscaler vaudra 1,135 action CrowdStrike. L'opération réunit la protection des terminaux (EDR) et la sécurité réseau en service cloud (SASE).

- Plus de 10 milliards de dollars de revenus récurrents annuels cumulés.
- Environ 2 000 clients communs.
- Finalisation prévue entre mi-2027 et janvier 2028.

CrowdStrike invoque les agents d'IA. Reste à voir la position des autorités de concurrence.
:::

::: details **ScreenConnect** : une faille notée 9,9 retourne l'outil de prise en main contre les techniciens.
Avec la CVE-2026-84869, un faux client envoie un fichier que le logiciel du technicien exécute sans rien afficher. Selon Huntress, l'attaque prend environ 9 secondes et installe un accès caché sur un poste qui contient souvent les identifiants de tous les clients. Huntress a observé au moins 688 000 tentatives sur 42 serveurs, entre le 20 octobre et le 16 novembre. Correctif : version 26.6.5 ou ultérieure ([The Hacker News](https://thehackernews.com/2026/11/hackers-exploit-critical-screenconnect.html)).
:::

::: details **CHU de Guadeloupe** : un rançongiciel paralyse l'hôpital, attaqué via un prestataire informatique.
L'attaque a eu lieu le soir du samedi 21 novembre et a déclenché le plan blanc. Le personnel travaille sans ordinateurs ni téléphones. Opérations, imagerie et consultations non urgentes sont reportées jusqu'au 27 novembre. Selon l'hôpital et l'ANSSI, les attaquants sont entrés par un prestataire non nommé, lui-même piraté quelques mois plus tôt ([Next](https://next.ink/brief-article/le-chu-de-guadeloupe-est-paralyse-par-une-cyberattaque/)).
:::

- GPT-6.2 Astra : 70 % ; Claude Fable 5.2 : 66,7 %.

Les postes seniors ne sont pas touchés, et l'usage simple (chat, résumés) n'a pas d'effet mesurable. Document de travail : une corrélation, pas une preuve de cause.

## Analyse

Les trois incidents de sécurité de l'essentiel ont un point commun : le risque vient d'un maillon indirect. Ghostscript est appelé par ImageMagick ou Pillow, binary-parser exécute du code qu'il génère lui-même, et la clé de Together AI a été commitée par un agent de code. Pour une stack Node.js ou PHP, l'audit des dépendances et des secrets doit donc couvrir ce que les outils font à la place du développeur.

Le délai de diffusion des correctifs reste un point à surveiller : Ghostscript 10.08.0 date de septembre, et des distributions majeures n'étaient pas à jour mi-novembre. Côté C++, reste à voir si le second vote des pays validera les contrats.

[NEXUS](/nexus), l'assistant auto-hébergé de Melchior JORDA, correspond au profil décrit par l'incident Together AI : une API Fastify qui envoie des requêtes à Gemini ou Claude. Le retrait du label ZDR à 125 points d'accès par OpenRouter montre que la non-conservation des prompts se vérifie plutôt qu'elle ne se suppose.
