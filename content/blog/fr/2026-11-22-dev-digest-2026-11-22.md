La sécurité domine cette édition, du routage de Fastify à la chaîne d'hébergement des modèles d'IA. Côté outils, plusieurs annonces visent à réduire le coût des agents de code.

## L'essentiel

::: details **Fastify** : cinq avis de sécurité visent @fastify/express, dont des contournements d'authentification corrigés en version 4.0.10.
Le module @fastify/express permet de réutiliser des middlewares Express dans une application Fastify. Chaque framework a son propre routeur. Quand les deux lisent un chemin différemment, un contrôle d'accès peut être sauté.

Le 20 novembre, les mainteneurs ont publié cinq avis de sécurité. Quatre sont critiques, un est élevé. Les deux principaux :

- CVE-2026-124626 (CVSS 9,1) : avec `app.use('/tenant/:tenantId', auth)`, une requête vers `/tenant/` saute `auth` mais atteint le handler, en configuration par défaut.
- CVE-2026-133120 (CVSS 9,1) : un chemin contenant `%2561` est décodé deux fois par le middleware, une seule fois par le code final.

Côté versions et contexte :

- correctifs dans la 4.0.10 ;
- la 4.0.11, publiée le 21 novembre, modifie aussi l'ordre des middlewares ;
- le dépôt compte dix avis en 2026, dont neuf critiques ou élevés.

Les sources ne disent pas si ces failles ont été exploitées. Ce type de bug, le « parser differential », touche aussi proxys, pare-feu et bibliothèques d'URL. Détails : [avis GHSA-662w](https://github.com/fastify/fastify-express/security/advisories/GHSA-662w-h4p6-jq4p), [avis GHSA-w877](https://github.com/fastify/fastify-express/security/advisories/GHSA-w877-hjcp-88rc) et [notes de version](https://github.com/fastify/fastify-express/releases).

> **Pour vous :** lancez `npm ls @fastify/express`, mettez à jour, et placez les contrôles de droits dans un hook `preHandler`, au plus près du code qui sert la donnée.
:::

::: details **Prompts piégés** : selon Dragos, trois hébergeurs de modèles d'IA ont été piratés depuis la mi-juillet.
L'entreprise Dragos, avec HD Moore (créateur de Metasploit), a publié le 19 novembre une étude sur la chaîne qui relie une application à un modèle : routeurs d'IA, puis hébergeurs. Sa méthode repose sur des canaris. Ce sont de faux secrets uniques qui déclenchent une alerte quand ils sont utilisés.

Le dispositif :

- environ 2 millions de prompts envoyés de juillet à novembre ;
- des canaris sous forme d'URL, de domaines et de clés AWS ;
- environ 2 000 chemins suivis chez différents fournisseurs.

Les constats :

- trois hébergeurs piratés ; dans deux cas, même des requêtes « zero data retention » (ZDR) ont été volées ;
- dans le pire cas, quelques centaines de fausses clés ont servi à des dizaines de milliers d'appels AWS ;
- le 1er novembre, l'attaquant utilisait ARTEX, un outil d'attaque piloté par IA ;
- un laboratoire d'IA chinois a visité les URL secrètes de plus de la moitié des prompts reçus ;
- un lien piégé est réapparu 24 jours plus tard dans une messagerie d'entreprise chinoise.

La plupart des fournisseurs ne sont pas nommés. L'étude de [Dragos](https://www.dragos.com/blog/ai-supply-chain-security-canary-tokens) reste une source unique.

> **Pour vous :** ne placez jamais de vrai secret dans un prompt, filtrez-les avant l'envoi et surveillez vos dépôts avec des jetons gratuits de [canarytokens.org](http://canarytokens.org/).
:::

::: details **TokenEconomizer** : le module libre de Microsoft Research réduirait de 18,4 % à 30,9 % le coût moyen des agents de code.
Microsoft Research a présenté TokenEconomizer le 16 novembre, sous licence MIT. L'équipe a d'abord mesuré le gaspillage de Claude Code sur 60 tâches :

- après cinq tâches dans un même projet, 30 % des actions répétaient un travail déjà fait ;
- 16 des 23 descriptions d'outils envoyées à chaque tour ne servaient jamais ;
- les 17 % de tâches ratées causaient 32 % des dépenses.

Le module ajoute trois mécanismes :

- des « micro-compétences », notes sur le projet gardées seulement si plusieurs sessions les confirment ;
- le retrait des outils inutiles ;
- un modèle « juge » qui repère quand l'agent tourne en boucle.

Résultats annoncés :

- 277 tâches, 5 combinaisons agent/modèle ;
- coût moyen par tâche en baisse de 18,4 % à 30,9 %, appels du module compris ;
- taux de réussite en hausse dans 4 combinaisons sur 5.

Ce qui est appris reste en local. Les mesures viennent de Microsoft, sur des benchmarks standard ([blog Microsoft Research](https://www.microsoft.com/en-us/research/blog/tokeneconomizer-learning-from-experience-to-make-ai-coding-agents-more-efficient/)).

> **Pour vous :** le [dépôt GitHub](https://github.com/microsoft/TokenEconomizer) prend en charge Claude Code, Codex, Copilot CLI et Pi ; à défaut, un fichier de notes projet tenu à jour (AGENTS.md, CLAUDE.md) applique la même idée à la main.
:::

::: details **Nabaztag** : Naboot, un firmware libre, apporte WPA3, TLS moderne et des mises à jour signées au lapin connecté de Violet.
Le Nabaztag dépendait des serveurs de Violet, fermés en 2011 après la faillite de l'entreprise. Une ancienne médecin généraliste devenue ingénieure devops a écrit Naboot, sous licence Apache 2.0. Elle raconte le projet sur [LinuxFr](https://linuxfr.org/news/un-nabaztag-une-medecin-et-une-ia-histoire-d-une-resurrection).

Le lapin repose sur un microcontrôleur ARM7 doté de 128 Kio de flash. Naboot apporte :

- le Wi-Fi WPA3 ;
- TLS 1.3, tenu dans 126 976 octets ;
- des mises à jour OTA signées ;
- un compilateur Python pour l'ancien langage du lapin, et un émulateur.

Un bug a empêché toute mise à jour OTA pendant cinq mois. Ses trois causes :

- l'outil signait la mauvaise version de l'image ;
- une bibliothèque cryptographique recevait le même tampon en entrée et en sortie, ce qui écrasait la clé ;
- la vérification de signature prenait environ 8 secondes, contre 2,09 secondes pour le watchdog.

Un quatrième bug a été trouvé avec AddressSanitizer sur l'émulateur. La version 1.2.1.0 est sortie le 20 novembre. L'autrice précise que Claude a écrit l'essentiel du code, mais qu'il « se trompe parfois avec assurance » ([code sur GitHub](https://github.com/ClaraVnk/nabaztag)).

> **Pour vous :** le [récit complet](https://cyberloutre.fr/nabaztag) sert de cas pratique sur le watchdog, la signature numérique et l'option `-fsanitize=address` de GCC et Clang.
:::

## Les autres sujets

La sécurité domine aussi le reste de l'actualité : failles critiques chez PHP et F5, incidents chez Rackspace, Microsoft et N-able, et sanctions de la CNIL. Côté IA, Gemini et Hugging Face s'attaquent eux aussi à l'efficacité des agents, tandis que plusieurs publications reposent sur des chiffres internes ou non vérifiés. Godot 4.8 approche de sa version stable, pendant que l'industrie du jeu poursuit ses suppressions de postes. Nvidia a perdu 14 % en une séance après des informations sur un examen de ses comptes.

### IA

::: details **Adaptateurs Hugging Face** : trois LoRA ajustent Qwen3.8-27B à un harnais d'agent précis.
Le 20 novembre, Hugging Face a publié un adaptateur LoRA par harnais (Pi, Hermes Agent, OpenCode) pour le modèle ouvert Qwen3.8-27B. Ils ont été entraînés par renforcement. Réussite au premier essai, selon les auteurs :

- Pi, sur 51 tâches SWE-bench Pro : de 40 % à 64 % ;
- Hermes, en terminal : de 44,7 % à 58,8 % ;
- [super-adaptateur](https://huggingface.co/harness-hub/Qwen3.8-27B-super-adapter) fusionné : de 39,5 % à 49 %.

Sur AutomationBench, les écarts restent dans le bruit ([blog Hugging Face](https://huggingface.co/blog/harness-adapters-at-scale)).
:::

::: details **Gemini Tool Retrieval** : l'API Gemini ne charge le schéma d'un outil que lorsque le modèle en a besoin.
Google a ajouté cette fonction en préversion le 19 novembre. On déclare un outil `tool_search` et on marque les autres avec `defer_loading: true`. Le modèle ne voit alors que le nom et la description courte.

Le réglage s'applique aussi aux serveurs MCP, sans frais supplémentaires ([blog Google](https://blog.google/innovation-and-ai/technology/developers-tools/gemini-api-tool-retrieval/)). Selon [PPC Land](https://ppc.land/google-shrinks-idle-tools-in-gemini-agents-to-about-26-tokens-each/) (non confirmé), un outil différé coûte environ 26 tokens. Google ne publie aucun chiffre d'économie.
:::

::: details **Distillation adversariale** : OpenAI détaille ses défenses contre la copie non autorisée de ses modèles.
La distillation entraîne un petit modèle à imiter un grand ; elle devient adversariale quand elle se fait sans permission. OpenAI combine refus appris, filtres et fermetures de comptes en masse. Une attaque qui extrait le raisonnement caché passerait de 54 % de réussite sur GPT-6 Astra à 0,2 % sur GPT-6.2 Astra.

OpenAI accuse nommément DeepSeek et des personnes liées à Moonshot AI. Ces accusations ne viennent que d'[OpenAI](https://openai.com/index/combatting-adversarial-distillation).
:::

::: details **Hy4 flash** : Tencent publie les poids d'un modèle à mélange d'experts de 220 milliards de paramètres.
Seuls environ 12 milliards de paramètres servent pour chaque token. Le mélange d'experts n'active que quelques spécialistes à la fois, ce qui accélère le modèle. Il lit jusqu'à environ 1 million de tokens et comprend les images. Sa licence est propre à Tencent : ce n'est pas une licence libre standard ([fiche Hugging Face](https://huggingface.co/tencent/Hy4-flash)).
:::

::: details **Agents de recherche chez OpenAI** : selon des chiffres internes, la réussite autonome des agents aurait doublé de mars à octobre.
Les mesures portent sur des tâches de deux à quatre heures confiées par les chercheurs d'OpenAI :

- réussite sans aide humaine : de 23 % en mars à 46 % en octobre ;
- surveillance d'un entraînement : 79 % ;
- écriture de code de service : 25 % ;
- dépense médiane : 2 400 $ par jour et par chercheur.

OpenAI parle de « frontière irrégulière ». Les chiffres sont internes et non vérifiés ; une partie du progrès vient d'un meilleur choix des tâches déléguées ([OpenAI](https://openai.com/index/research-acceleration-jagged-frontier/)).
:::

::: details **Rapports des modèles ouverts** : une revue de 40 rapports techniques constate que peu de nouveautés sont démontrées.
Seules 19 des 73 nouveautés revendiquées s'appuient sur une comparaison contrôlée, qui ne change qu'une variable à la fois. Un seul rapport publie ensemble les données d'entraînement, leur volume et la puissance de calcul utilisée. Ouvrir les poids ne veut donc pas dire tout dévoiler. L'étude n'a pas encore été relue par des pairs ([arXiv 2611.20003](https://arxiv.org/abs/2611.20003)).
:::

### Sécurité

::: details **Rackspace Spot** : des identifiants fuités ont exposé les Secrets Kubernetes de clients pendant environ 22 heures.
Le 17 novembre, un intrus s'est fait passer pour des utilisateurs de certaines organisations clientes. Il pouvait créer des pods, lire les Secrets, lister machines et disques, et accéder aux jetons d'API. La console d'administration est restée longtemps en panne, ce qui empêchait les clients de changer eux-mêmes leurs identifiants.

Rackspace demande de refaire jetons et fichiers de connexion, de changer les mots de passe stockés et d'auditer les journaux. Le nombre de clients touchés n'est pas connu (source unique : [BleepingComputer](https://www.bleepingcomputer.com/news/security/rackspace-spot-breach-let-hackers-access-customer-kubernetes-secrets/)).
:::

::: details **PHP** : 18 failles corrigées, mais plus de 200 000 sites en .fr restent sur une version vulnérable.
PHP a publié ses correctifs le 19 novembre. Ils couvrent les versions maintenues, de 8.2 à 8.5. La pire faille, notée 9,2, touche PHP-FPM et permet d'exécuter du code sans authentification dans certaines configurations ([BleepingComputer](https://bleepingcomputer.com/news/security/php-security-updates-fix-18-flaws-including-critical-rce-bugs)).

[Next.ink](https://next.ink/268806/php2shell-face-aux-risques-la-migration-avance-trop-doucement/) a scanné environ 500 000 sites en .fr affichant leur version. Moins de 10 000 sont passés aux versions corrigées. Le chiffre est peut-être surestimé, car certains hébergeurs corrigent sans changer le numéro.
:::

::: details **Microsoft Entra** : un bug exploité de Connect Health exposait des informations sur d'autres organisations clientes.
Le bug, introduit le 23 juillet, donnait accès aux e-mails des administrateurs, au nom, au pays et au type de licence d'autres organisations. Microsoft l'a repéré le 9 novembre et corrigé le 19. Aucun mot de passe ni jeton n'a fuité ; le risque principal est l'hameçonnage ciblé des administrateurs ([BleepingComputer](https://www.bleepingcomputer.com/news/security/microsoft-entra-connect-health-flaw-exploited-to-steal-tenant-data/)).
:::

::: details **F5 BIG-IP** : six failles critiques de débordement de tampon reçoivent des correctifs d'urgence.
Ces équipements répartissent et filtrent le trafic devant les sites de grandes entreprises. Chaque faille est notée 9,8 en CVSS et dépend d'une fonction de configuration précise. Les correctifs datent du 18 novembre, et aucune exploitation n'était alors connue. Shadowserver suit plus de 177 000 équipements exposés sur Internet ([Censys](https://censys.com/advisory/cve-2026-121805/), [BleepingComputer](https://www.bleepingcomputer.com/news/security/f5-releases-emergency-patches-for-critical-big-ip-rce-flaws/)).
:::

::: details **N-able** : la panne mondiale de Mail Assure et SpamExperts venait finalement d'une intrusion.
N-able fournit des outils aux prestataires qui gèrent l'informatique d'autres entreprises. Elle a d'abord évoqué un problème de configuration. Un jour plus tard, elle a reconnu un accès non autorisé à un serveur. L'entreprise dit n'avoir aucune preuve d'accès aux boîtes mail des clients ([BleepingComputer](https://www.bleepingcomputer.com/news/microsoft/n-able-says-recent-security-breach-led-to-major-service-outage/)).
:::

::: details **BADBOX 3.0** : un botnet de boîtiers TV Android atteint environ 40 milliards de requêtes publicitaires par jour.
Les boîtiers, bon marché et souvent vendus déjà infectés, simulent de faux spectateurs de publicités. Ce volume dépasse plus de trois fois l'ancien record. Les appareils servent aussi de proxys résidentiels : des criminels font passer leur trafic par la connexion des propriétaires pour se cacher. Les boîtiers sans marque appellent à la méfiance ([BleepingComputer](https://www.bleepingcomputer.com/news/security/badbox-30-botnet-returns-with-record-breaking-40-billion-daily-ad-requests/)).
:::

::: details **CNIL** : 38 sanctions simplifiées visent notamment des mots de passe d'un caractère et le hachage SHA-1.
La procédure simplifiée plafonne l'amende à 20 000 € et ne nomme pas l'organisme. De juin à octobre, les sanctions ont totalisé 302 800 €. Environ une douzaine portent sur les cookies, autant sur la sécurité.

Un site acceptait un mot de passe d'un seul caractère, un autre hachait les mots de passe en SHA-1, méthode dépassée. bcrypt et Argon2 sont conçus pour cet usage ([CNIL](https://www.cnil.fr/fr/38-sanctions-simplifiees)).
:::

### Web, cloud et outils

::: details **Next.js** : le framework compte 51 avis de sécurité en 2026, une hausse attribuée aux outils d'IA.
Évolution du nombre d'avis :

- 2024 : 6 ;
- 2025 : 14 ;
- 2026 : 51.

Selon l'équipe, 70 % des failles de cette année touchaient du code d'au moins un an. Ses réponses : programme de primes, audit externe et mises à jour de sécurité mensuelles annoncées à l'avance. Depuis la version 16.4, `next dev` signale une version vulnérable ([blog Next.js](https://nextjs.org/blog/how-were-using-ai-to-make-nextjs-more-secure)).
:::

::: details **Debian 13.8** : la huitième mise à jour de « trixie » regroupe environ 139 avis de sécurité.
Publiée le 21 novembre, ce n'est pas une nouvelle version mais un regroupement de correctifs. Elle inclut aussi 122 corrections de bugs. Elle touche notamment glibc, sudo et un contournement du démarrage sécurisé dans GRUB. Un `apt update && apt upgrade` suffit à l'appliquer ([Debian](https://www.debian.org/News/2026/20261121)).
:::

## Analyse

La faille Fastify et l'étude de Dragos ont un point commun : un composant intermédiaire qui ne se comporte pas comme prévu. D'un côté, un module de compatibilité dont le routeur diverge de celui d'Express ; de l'autre, des hébergeurs qui exposent des prompts pourtant couverts par une promesse ZDR. Les API Fastify, comme celle de [NEXUS](/nexus), sont concernées dès qu'elles réutilisent des middlewares Express via @fastify/express.

Côté agents, TokenEconomizer, Tool Retrieval et les adaptateurs de Hugging Face visent le même levier : moins de contexte envoyé et moins d'appels d'outils inutiles. Les gains sont mesurés par leurs auteurs, et Google ne publie aucun chiffre. Reste à voir si ces résultats tiennent hors des benchmarks, alors que les adaptateurs n'apportent déjà rien de net sur AutomationBench.

Pour les projets PHP, l'écart entre correctifs publiés et versions déployées en .fr est un point à surveiller.
